## 1. Layout resolvido (tabela de images)

O problema aberto estava no **offset**, não no stride: os pares (offset,size) do header para as tabelas ≥15 apontam **8 bytes além** do início real da tabela (em dec[]). Com isso:

Início real = pair18.offset−8 (114: 0xa2aae4; 195: 0x96b9e4); contagem = size/88 = 11681 (114) / 10997 (195).
- **images**: stride **0x28 (40B)**, 10×i32 `nameIndex, assemblyIndex, typeStart, typeCount, exportedTypeStart, exportedTypeCount, entryPoint, token, customAttrStart, customAttrCount`; começa logo após o fim das typeDefs (início real = pair19.offset−8). Os 3 candidatos de stride antigos (0x40/0x38/0x34) eram falsos positivos: liam as colunas com deslocamento de 8 bytes.
- **methods**: 36B, início real 114=0x393dd4 (anchor antigo 0x393dcc estava −8), 195=0x340690; validação `method.declaringType == typeDef` → **0 divergências em 92.976 (114) e 87.203 (195) métodos**.
- **nestedTypes**: tabela fica *antes* de `interfaces` (par 15 = interfaces), base = pair15.offset−8−4·Σnested; `nestedStart` = word 12.
- strings: 114 @0xcda08, 195 @0xbd8b8 (derivado de `<Module>` + nameIndex da typeDef 0).
